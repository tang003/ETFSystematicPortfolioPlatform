# 17 面试项目说明

本文档用于把 ETF Systematic Portfolio Platform 整理成简历和面试可展示的项目经历。它不是系统运行手册，而是帮助面试官快速理解项目复杂度、技术深度和候选人贡献。

## 项目一句话

ETF Systematic Portfolio Platform 是一个面向个人 ETF 投研和资产配置的全栈量化平台，基于 FastAPI、Vue 3、PostgreSQL、Redis 和 Docker Compose 构建，覆盖 ETF 数据同步清洗、因子计算、策略轮动、目标组合、持仓分析、定投建议、风控调仓、回测复盘、AI 投研报告、多用户权限和生产部署。

## 可以重点讲的技术点

### 1. raw/clean 双层行情数据模型

外部行情先写入 `market_data_raw`，保留来源、原始 payload 和同步状态。清洗后再写入 `market_data_clean`，统一日期、价格、成交量、成交额和数据源口径。

面试表达：

> 我没有让策略直接依赖外部 API 返回值，而是设计了 raw/clean 两层数据。raw 用于追溯外部来源，clean 用于因子、策略、回测和投研页面，避免字段口径不一致影响结果。

### 2. 后台任务和任务中心

行情同步、全流程投研、历史初始化、行情补齐和每日维护都可能耗时较长，所以系统使用 worker 执行后台任务。API 只负责创建任务和返回任务 ID，前端通过任务中心查看步骤、进度、耗时和失败原因。

面试表达：

> 我把长任务从请求响应链路里拆出去，生产环境由 worker 消费任务，Redis 负责心跳和锁，PostgreSQL 记录任务、步骤和结果。这样前端不会因为行情同步或全流程计算阻塞。

### 3. 多因子 ETF 轮动策略

系统支持趋势、动量、波动、回撤、流动性和 Alpha 等因子，策略运行后生成目标组合，并保留 `run_id`、策略代码、版本和运行日期，方便后续审计和回测。

面试表达：

> 策略不是写死在页面里，而是后端服务根据因子和策略配置生成目标权重。每次运行都有 run 记录，方便追溯某个目标组合是由哪次策略、哪套参数生成的。

### 4. 风控和回测闭环

系统不会自动交易，只生成风控检查结果和调仓建议单。回测模块支持月度轮动、买入持有、月度追加资金、手续费、滑点、净值曲线、交易记录和指标落库。

面试表达：

> 我把策略建议和交易执行严格分开。系统只做目标组合、风控检查和调仓建议，不接券商、不自动下单。回测也尽量复用清洗行情和策略逻辑，避免前后口径分裂。

### 5. AI 投研不是简单聊天

DeepSeek 只用于总结和表达增强，输入上下文来自本地行情、因子、持仓、目标组合、新闻和报告。AI 不能编造收益、规模、费率或行情，也不能直接给确定性交易指令。

面试表达：

> 我没有把 AI 当成交易信号，而是把它放在投研解释层。系统先用本地数据和规则型 Agent 形成结构化上下文，再让 DeepSeek 生成中文总结，最后把分析历史落库。

### 6. 权限、审计和安全

系统支持环境变量兜底管理员和数据库用户，角色包括 `admin`、`researcher`、`viewer`。高风险接口需要管理员，普通投研写入需要研究员或管理员，观察者只读。变更类 API 写审计日志，敏感 query 参数脱敏，请求正文不落审计日志。

面试表达：

> 我把权限做在后端依赖层，前端只是优化体验。即使用户手动调用 API，后端仍会检查角色。审计日志只记录元信息和脱敏参数，避免把 token 或密码写进数据库。

### 7. 生产部署可落地

生产环境使用 Docker Compose 部署 PostgreSQL、Redis、API、worker 和前端容器，外部 Caddy 负责 HTTPS。部署脚本会自动拉取代码、备份数据库、校验 Compose、构建镜像、启动容器并检查 API ready。

面试表达：

> 这个项目不是只在本地跑 demo。我做了生产部署脚本、健康检查、数据库备份和 worker 心跳，线上可以通过 ready 接口判断 API、数据库和 worker 状态。

## 面试官可能追问

### 为什么不用前端直接请求 Tushare？

前端直接请求外部数据源会暴露 Token，也不利于限频、重试、清洗和审计。系统统一由后端同步入库，前端只读取本地数据库结果。

### 为什么要区分 `market_data_raw` 和 `market_data_clean`？

raw 用于保存外部来源和原始响应，clean 用于统一业务计算口径。这样既能追溯数据来源，也能避免策略、回测和页面混用不同字段。

### 如何避免回测未来函数？

回测读取本地清洗行情，并按历史调仓日、因子取值日和交易执行日拆分流程。策略运行和回测都尽量复用同一套策略构造逻辑，避免为了回测单独写一套“更好看”的逻辑。

### 如果 Tushare 不可用怎么办？

系统不会让前端直接依赖外部接口。外部同步失败会记录错误、保留本地已有数据，并在数据健康页和任务中心给出失败原因。共享 token 场景下也会限制同步范围和请求间隔。

### AI 投研有没有投资建议风险？

AI 只做总结和解释，不直接生成交易指令。报告里会明确说明系统不自动下单、不承诺收益，所有交易动作需要人工确认。

### 多用户隔离做到什么程度？

当前已完成账号、角色和部分业务数据隔离。当前持仓、持仓分析、定投计划、定投建议、报告和 AI 投研历史按用户隔离；ETF 池、行情、因子和目标组合仍是共享研究数据。后台任务归属和更细粒度权限是后续优化项。

## 项目边界

已实现：

- ETF 数据同步和主资料管理。
- 行情 raw/clean 分层。
- 数据质量检查和补齐任务。
- 因子计算和 ETF 轮动策略。
- 目标组合、持仓分析、定投建议、风控调仓。
- 回测和报告。
- AI 投研总结。
- 用户管理、角色权限、操作审计。
- Docker Compose 生产部署。

未实现或不在当前边界：

- 不连接真实券商交易账户。
- 不自动下单。
- 不直接操作资金。
- 未实现分钟级行情和实时行情。
- 未实现完整 ETF 成分、行业暴露和估值因子。
- 后台任务归属和更细粒度权限仍需继续完善。
